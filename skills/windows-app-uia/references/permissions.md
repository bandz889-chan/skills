# 권한과 실행 조건 (Windows)

맥처럼 "손쉬운 사용" 허용 목록은 없다. UIA와 창 메시지는 같은 데스크톱의 일반 프로그램이면 쓸 수 있다.
대신 아래에서 막힌다.

## 권한 수준 (UIPI)

- 낮은 권한 프로세스는 높은 권한 창에 `SendMessage` · `PostMessage`를 보낼 수 없고, UIA 값도 못 바꾼다.
  오류 없이 무시되는 경우가 많다.
- 확인: 작업 관리자 → 세부 정보 → "권한 상승" 열. 대상 앱이 "예"면 헬퍼도 막힌다.
- 대응: 대상 앱을 일반 권한으로 다시 띄운다. 헬퍼를 관리자 권한으로 돌리는 것은 마지막 수단으로만 사용자에게 설명한다.
- `uiAccess` 서명 앱은 일반 배포에서 쓰지 않는다.

## 데스크톱 상태

- 화면 잠금, 원격 데스크톱 최소화 · 연결 끊김 상태에서는 UIA 트리가 비거나 키 메시지가 처리되지 않을 수 있다.
- 서비스 · 예약 작업(세션 0)으로 돌리면 사용자의 창이 보이지 않는다. 사용자가 로그인한 세션에서 실행한다.

## 보안 프로그램

- 일부 백신 · 보안 프로그램은 다른 앱에 키 메시지를 보내는 프로그램을 의심한다. 차단되면 사용자에게 알리고 멈춘다.
- 헬퍼가 PowerShell 실행 정책 때문에 막히면 스크립트 대신 `py helper_action.py`로 부른다.

## 헬퍼가 시작할 때 확인할 것

- `sys.platform == "win32"` 아니면 `windows_required`.
- 대상 프로세스가 없으면 `app_not_running`.
- 대상 창의 무결성 수준이 더 높으면(가능하면 `OpenProcessToken`으로 확인) `target_elevated`.
